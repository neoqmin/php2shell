## 2. PHP2Shell — CVE-2026-109618 / CVE-2026-109619

### 2.1 Timeline

| Date/time | Details |
|---|---|
| 10-17 | First attack attempt observed in Amazon MadPot honeypots, 4 days before disclosure (cited by Tenable) |
| 10-20 | The CVE IDs leaked first on social media and Hacker News. The PHP security team pre-announced a 10-21 14:00 UTC release |
| 10-21 | The disclosure date, originally 10-22, was moved up by a day; the patch and advisory were published. The same day CISA issued an alert and Cloudflare deployed WAF rules |
| 10-21~ | Attack attempts with a variety of payloads, apparently from multiple actors, were observed |
| 10-22 | Vendor detection plugins and product patches were released (Tenable, Rapid7, etc.). Not listed in CISA KEV as of this point |

- Discovery: Calif (researcher LCFR). The PHP Foundation credited Calif, OpenAI, Wiz, and others. Both Calif and Wiz stated they used AI models.
- The leaked CVEs circulated with a CVSS of 10.0, but the PHP Foundation stated that score was wrong. The official score is 9.2.

### 2.2 Technical root cause

#### CVE-2026-109618 — Cleanup of partially initialized request data during OOM (GHSA-w8hw-w9fx-j79w)
- When PHP exceeds `memory_limit`, it aborts the request via `longjmp()`.
- If this abort happens **in the middle of parsing a multipart (form/file upload) request**, internal request data is left only partially initialized.
- The subsequent cleanup stage then trusts this data. As a result it frees uninitialized memory — that is, attacker-controlled data left over from a prior allocation. This causes memory corruption and leads to RCE.
- **Apache mod_php** performs cleanup even when request startup fails. Therefore the attack succeeds before application code runs (demonstrated).
- **PHP-FPM** terminates the worker on startup failure, which blocks this path. However, analysis suggests it may still be vulnerable after startup succeeds. A full FPM exploit has not been reported.
- RCE over HTTP has been reported even under default input and memory-limit settings.

#### CVE-2026-109619 — Cross-request stale-state Use-After-Free (GHSA-6wmf-4rv5-p3rp)
- Internal state owned by a request persists even after its memory is freed. When the **same worker** processes the next request, it reads this stale state before initialization.
- Trigger paths:
  - A fatal error (memory exhaustion, timeout) interrupts state cleanup
  - Certain non-fatal shutdown diagnostics repopulate the error state after a reset
- Confirmed RCE paths (Rapid7):
  - **mod_php + PHP 8.5's `fatal_error_backtraces`** (enabled by default)
  - Session-lifecycle RCE via **`session.upload_progress`** (enabled by default, no `session_start()` required). Holds on both mod_php and FPM
- FPM attack chain: ① app behavior that leaves stale state → ② fatal error → ③ a second request routed to the same worker consumes that state via upload progress. With many or recycled workers the success rate drops, but the condition itself does not disappear.
- Memory disclosure (information leak) is also a confirmed impact.

### 2.3 Scope of impact

- **SAPI**: Every installation that serves web requests is affected. This includes PHP-FPM, Apache mod_php, php-cgi, FrankenPHP, and LiteSpeed, and PHP rated **mod_php as the highest risk**.
- PHP-based CMSes such as WordPress, Drupal, and Joomla are also exposed depending on the runtime version.

| Branch | Status |
|---|---|
| 8.5 | Fixed in **8.5.12** |
| 8.4 | Fixed in **8.4.27** |
| 8.3 | Fixed in **8.3.36** |
| 8.2 | Fixed in **8.2.35** (8.2 end of support is 2026-12-31) |
| 7.4 / 8.0 / 8.1 | No official release. PHP published minimal source backports (GitHub branches `PHP-x.y-CVE-2026-109618-109619`). You must use distro / LTS vendor packages or upgrade |
| 7.3 and below (including PHP 5) | EOL. No patch. Impact was confirmed even on PHP 5 (watchTowr) |

- Linux distributions and LTS vendors received the patch in advance. remirepo announced it would not ship an update on 10-21 itself.

### 2.4 CVSS

- Both CVEs are **CVSS v4.0 9.2**
- `CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N`
- The AC:H / AT:P rating means success depends on environmental conditions such as memory layout and worker reuse. This matches the phenomenon of the PoC working only under specific environment combinations.

### 2.5 Exploitation status (sources differ)

| Source | Description |
|---|---|
| Amazon Threat Intel (cited by Tenable) | First attempt 10-17; "broadly exploited in the wild" from 10-21. Success unknown |
| watchTowr | In-the-wild attacks observed from 10-21 |
| Rapid7 | No actual attacks observed. Many reports of attack **attempts** |
| CERT-EU | Since a PoC is circulating, it is highly likely that attacks are already underway |
| CISA (10-21 alert) | Not observed at disclosure time. Not in KEV as of 10-22 |
| PHP Foundation | Could not confirm a working exploit at disclosure time |

- **PoC**: Several public PoCs exist. Each works only on a specific OS/PHP/web-server combination, and none is yet reliable in a general sense (Rapid7). watchTowr reproduced both vulnerabilities.
- For reference, past PHP-related KEV listings include CVE-2024-4577 (PHP-CGI), CVE-2019-11043 (PHP-FPM), and CVE-2012-1823. The first two were confirmed to be abused by ransomware.

### 2.6 Response measures

**The only complete solution is patching.** PHP stated it cannot be fully mitigated by configuration changes alone.

Temporary mitigations when patching is not possible:

**CVE-2026-109618**
- Set `memory_limit=-1`. Pin it via `php_admin_value` in the FPM pool or Apache config so the app cannot override it, and verify that no other pool, directory, or app config reverts it to a finite value.
- Set `post_max_size=8M` (if uploads are unnecessary) or `32M` (if uploads are needed), and set `upload_max_filesize` smaller than that.
- At the proxy / web-server layer, limit post-decode size, the number of fields and parts, the number of headers per part, and the nesting depth. Include requests without a `Content-Length` in scope.
- Apply a container or cgroup memory limit. If possible, arrange for only the worker to be killed. Do not use `RLIMIT_AS` / `RLIMIT_DATA`.
- If the app does not use multipart, block multipart requests in front of PHP.

**CVE-2026-109619**
- Set `session.upload_progress.enabled=0`. It must go somewhere **applied before request parsing** — php.ini, the FPM pool, or the server config. `ini_set()` and the FPM `.user.ini` are applied too late to be effective. Restart all workers after setting it.
- On PHP 8.5, set `fatal_error_backtraces=0` and restart all workers.
- Eliminate attacker-triggerable fatal errors and timeouts, and clean up incorrect or deprecated per-request settings.
- Hiding errors with `error_reporting`, `display_errors`, `log_errors`, or `@` has **no effect**.

**Common**
- Isolate internet-exposed PHP systems until patched. CISA recommended taking systems that cannot be patched, or that are 8.1 or below, offline.
- A WAF (Cloudflare, etc.) is a stopgap that applies only to traffic passing through that path.
- For third-party software that bundles PHP, check the NCSC-NL list at `github.com/NCSC-NL/php2shell`.

### 2.7 Detection

- No public IOCs (hashes, IPs, domains, payload strings) exist yet.
- Scanners:
  - Tenable Nessus 369483, WAS 115719–115722
  - Rapid7 InsightVM/Nexpose remote unauthenticated check
  - Velociraptor artifact `Generic.Applications.PHPInventory` for collecting a PHP inventory
- For compromise investigation, scope from **10-17**, not the disclosure date (Amazon).
- The absence of related logs is not evidence of safety (Rapid7).

## 3. 2026-09-24 security release (8.2.34 / 8.3.35 / 8.4.26 / 8.5.11)

About 10–11 CVEs were fixed across OpenSSL, SOAP, Phar, HTTP stream, mysqlnd, and Windows file I/O.

| CVE | Details | Severity |
|---|---|---|
| CVE-2026-91765 | The SOAP XML parser `cleanup_xml_node()` recurses without a nesting-depth limit. A deeply nested SOAP request can crash a `SoapServer` endpoint, and on FPM it exhausts the worker pool. No authentication required | CVSS v3.1 7.5 (availability) |
| CVE-2026-91768 | IPv6 FastCGI access-control bypass | — |
| CVE-2026-91766 | On HTTP stream redirect, the `Authorization`/`Cookie` headers leak to a different host | — |

- No actual exploitation of CVE-2026-91765 has been confirmed. Some sites (TheHackerWire) labeled it "Zero-Day / RCE / KEV Linked", but this does not match other sources and is hard to trust.

## 6. Checklist

- [ ] Identify PHP-using systems across the entire infrastructure. Prioritize internet-exposed systems and include third-party products that bundle PHP.
- [ ] Determine the SAPI (prioritize in the order mod_php > FPM/CGI).
- [ ] Update to 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 or above. For distro packages, verify the backport in the changelog.
- [ ] For 8.1 and below, choose one of: upgrade, apply a backport, or isolate.
- [ ] Until patched, apply the mitigations from §2.6 and **restart all workers**.
- [ ] Inspect web logs and process anomalies (worker crashes, abnormal child processes) from 10-17 onward.
- [ ] For systems running 8.2, draw up a migration plan ahead of the year-end EOL.

## 7. Related open-source test tool reference

> Only addresses are recorded. The sources were not downloaded or run, so their behavior and safety are unverified.
> Use for defensive purposes only, such as asset inspection and patch verification. Run only on systems you own or are authorized to test.
> Review third-party repository code directly before running it (risk of tampering / malicious insertion).

### 7.1 PHP2Shell (CVE-2026-109618 / CVE-2026-109619)

**Detection · scanning (defensive / asset-inspection use)**
- [ProjectDiscovery nuclei-templates](https://github.com/projectdiscovery/nuclei-templates) — Official template set. Passive (non-exploit) PHP-version-based check (the CVE templates confirm the version via the X-Powered-By header)
- [ProjectDiscovery — PHP2Shell analysis / inspection guide](https://projectdiscovery.io/research/php2shell)
- [Ademking/php2shell-nuclei-templates](https://github.com/Ademking/php2shell-nuclei-templates) — A collection of nuclei templates for the two CVEs (some write a session file to the target, so use only on owned/authorized systems)
- [silascutler — Censys query gist](https://gist.github.com/silascutler/c7f04537a79ace89569f979d964af0f9) — A Censys query for finding exposed assets

**Isolated lab for patch verification (Docker A/B environment)**
- [0x4148/CVE-2026-109618-php2shell-lab](https://github.com/0x4148/CVE-2026-109618-php2shell-lab) — A Docker lab comparing vulnerable / fixed versions

> Public PoC repositories containing exploit code are not linked in this document.
> Each PoC works only on a specific OS/PHP/web-server combination, and none is reliable in a general sense (Rapid7).

### 7.2 CVE-2026-91765 (SOAP unbounded recursion DoS)

- Official advisory: GitHub Security Advisory **GHSA-rgrp-mwpx-f6rm**
- No trustworthy public PoC repository has been confirmed. Aggregator sites report its existence inconsistently. Reproduction is done by sending a deeply nested SOAP request to a `SoapServer` endpoint, and only in a dedicated lab.
